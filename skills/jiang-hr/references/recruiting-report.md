# 招聘汇报

## 目标

把招聘平台导出、HR 台账和既有汇报模板合并成可回指、可解释的招聘汇报，同时保留不同数据源的口径边界。

## 工作流

1. 识别每个文件的来源、时间范围、统计粒度、工作表和关键字段。
2. 分开列出平台能够提供的字段与 HR 台账补充的字段，不跨来源补写数据。
3. 核对时间范围、岗位名称、渠道名称和候选人主键；同名异义或异名同义时先建立映射表。
4. 根据实际流程生成招聘漏斗。常见节点为“打招呼 → 有效沟通 → 收到简历 → 初筛通过 → 约面 → 到面 → 面试通过 → Offer → 接受 Offer → 入职”，但不得硬补源数据中不存在的节点。
5. 生成岗位进度表、渠道对比和异常差额表。
6. 计算每一步转化率和流失人数，找出总盘、岗位和渠道的主要断点；建议必须基于这些断点，不能把建议写成已发生的事实。
7. 按用户提供的周报或月报模板整理管理层摘要，区分事实、推断、待确认、主要卡点、优化建议和下一步动作。

## 口径规则

- 平台字段只按平台导出统计，不把 HR 台账中的动作反填成平台数据。
- 约面、到面、复试、Offer、入职等平台没有的节点，以 HR 台账为准并标注来源。
- 未知值保持空白或标“待确认”，不用 0 代替未知。
- 每个结论都能回指到具体文件、工作表和字段。
- 对候选人去重时优先使用稳定主键；只靠姓名无法确认时保留待确认项。
- 用户要求隐藏渠道时，先建立受控映射，再统一显示为渠道A、渠道B等匿名名称。

## 已有 Excel 结果复用模式

如果用户提供的 Excel 已经包含招聘看板、招聘台账、岗位进度、渠道对比或管理层周报，并明确要求“不要重新生成、不要重新计算”，把该 Excel 视为唯一获批结果源：

- 本次任务只做读取、可视化和文档排版，不重算公式、不重新汇总台账、不改写结果、不补充另一套数字。
- 优先读取招聘看板、岗位进度、渠道对比和管理层周报中的现有显示结果；除非用户明确要求复核，否则不从底层台账重新推导。
- 漏斗图和结论只使用 Excel 已有结果。制作 HTML、PNG 或 Word 属于呈现转换，不得借此改变数字或口径。
- 用户限制输入范围时，不再读取同目录里的原始平台导出或 HR 台账。
- 对用户不展示文件扫描、字段映射、公式读取、内部校验或排版步骤；完成后只给结果文件、简短结论和待确认项。

## 默认交付：Word 招聘进度周报

用户要求 Word，或只说“生成招聘汇报”而没有指定格式时，默认生成一个可打开的 `.docx` 文件。只有用户明确要求 Excel 时，才改为 Excel 交付。

Word 的生成顺序：

1. 先用经过核对的数据制作三张图：总招聘漏斗、岗位招聘漏斗、渠道招聘漏斗。没有岗位或渠道维度时，省略对应图，不编造数据。
2. 优先用 HTML 制作 16:9 图表页面，再导出高清 PNG 后插入 Word。建议画布为 1600×900，导出时使用 2 倍像素；插入前检查文字没有截断、数字没有遮挡、渠道匿名一致。
3. Word 至少包含：标题与时间范围、核心数字、三张漏斗图、关键结论、事实与待确认、主要卡点、招聘优化建议、下周动作。
4. 图表使用内嵌图片，不引用临时网页或外部链接；最终文件移动后仍能正常显示。
5. 保存 Word 后逐页检查，确保图片清晰、页面不多出空白页、页尾建议完整可见。

招聘优化建议至少覆盖实际数据支持的方向，例如：统一初筛标准、提高到面稳定性、按岗位补充证据、补齐渠道成本。没有事实支持的方向不要硬写。

## 报告内容

1. 招聘漏斗：节点人数、上一步转化率、流失人数和数据来源。
2. 岗位进度表：岗位、状态、各节点人数、主要卡点和下一步动作。
3. 渠道对比：简历量、到面率、面试通过率、Offer 接受率和入职数。
4. 异常差额表：无法对账的岗位、渠道、节点和差额说明。
5. 管理层摘要：关键结论、事实、推断、待确认、主要卡点和下周动作。

对用户的最终回复只保留招聘结论、结果文件位置、主要卡点和待确认项。不要展示数据清洗、字段映射、口径判断或计算过程，也不要使用“已经完成”“已经做出来了”等表述。

## 验收

- 总盘与岗位、渠道拆分能够对上；无法对上的差额单列。
- 漏斗人数不应无解释地向后增加。
- 转化率分母为 0 时显示“—”，不产生公式错误。
- 事实、推断和待确认分开呈现，关键结论能够回指原始字段。

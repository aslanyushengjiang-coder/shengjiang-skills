# 食品品牌图：先判断，再组装提示词

用于菜品、甜品、酒饮的品牌产品图，以及“更有质感”“换一种风格”“前后变化明显”的任务。先读 [输入合同](input-contract.md) 和 [六层锁](lock-system.md)，再从 [食品风格模板](food-style-prompts.md) 选择一个主风格。这里补充摄影判断，不替换 S01–S12 的用途、事实和运行路由。

## 1. 先看图，写出可检查的判断

每个商品都实际打开原图；不能只按文件名、菜名或上一张的结论写提示词。只保留简短设计依据、输入事实和决策，不要求输出内部思维过程。

| 判断 | 要写清什么 | 影响什么 |
| --- | --- | --- |
| 用在哪里 | 外卖缩略图、菜单卡、品牌海报、网站首屏或自然到店图 | 主体大小、留白和镜头距离 |
| 原图好在哪里 | 如番茄的红、肉的纤维、玻璃透光、白盘完整 | 原图已经好的地方不为“升级”而改坏 |
| 原图缺什么 | 如桌面杂乱、背景无识别度、主体和背景同色 | 只处理可见问题，不泛写“高级、大牌、8K” |
| 商品是什么形状 | 高杯、宽盘、深碗、扁平披萨、层叠甜品 | 构图位置和安全边界 |
| 哪些事实已知 | 可见块数、杯型、酱汁颜色、摆盘；未知项另列 | 不猜克重、酒款、原料、口味或做法 |
| 原图的拍摄条件 | 俯拍或斜拍、光线方向、硬软、反射 | 选择能与原照片相容的背景 |
| 用户要多大变化 | 轻修、明显品牌化、多个风格探索 | 不能用同一套浅米色背景回答所有请求 |

图片来源与用途分开记录。真实门店照片用 `authoritative-dish`；AI 示例用 `demo-fixture` 并保留概念标识；审美图片用 `style-only`。同一批里每张图都绑定 `item_id`，不能拿相似菜名串图。

## 2. 选择风格，不按菜系套刻板印象

按下面顺序决定，不让装饰盖过菜品：

1. 优先遵守用户指定风格、真实品牌色和本次用途。品牌色已经确定时，不用模板示例色替换。
2. 从 F01–F10 中找与原图视角、材质、主色相容的风格。选一个主风格，写一句理由；有明确的不适配点就排除。
3. 没有指定风格时，Agent 自主选最合适的一种；用户要求多种方案时，选结构和光线确实不同的方向。不要把十种风格混进一张图，也不强迫每次先做十张试稿。
4. 同一品牌同一批次先固定背景结构、光线方向、器皿保护规则、主体尺度和留白习惯。不同商品可用已批准的子配色，不能一张田园、一张夜店、一张极简却称为一套品牌物料。
5. 跨风格探索分 `variant_id`；商品身份不变。圆弧色块只是 F01，不能把它当作所有店的默认审美。

用途优先于风格：外卖主图沿用 S01 的主体识别要求；品牌海报可以扩大环境与留白；自然到店图不强加摄影棚背景。没有俯拍原图且必须原样保留菜品时，不选要求顶视图的 F06；改选同视角风格或索取合适原图，不让模型补出食物背面。

## 3. 把“前后变化”写成具体修改

用户要求明显品牌化时，在允许范围内至少明确两项可见变化，并保留原图对照：

- 背景结构：平桌面变为有层次的纸面、墙面、台面、平面分区或真实场景。
- 取景和留白：调整原照片在画布的位置与尺度，完整保留主体；需要改变拍摄视角时必须有相应来源或明确概念授权。
- 光影：让背景光向、接触阴影、反射与原图一致；保护原像素的任务不能靠重绘菜品来补光。
- 材质关系：让陶瓷、纸、木、金属、玻璃各有区别，不全变成平滑塑料。

仅调饱和度、统一加黄、略微放大或只把米色换成另一种米色，不算“明显品牌化”。但当用户只要自然轻修时，不强制大改。若允许修改的范围不足以满足明显变化，解释限制，不能擅自突破保护区域。

色彩丰富来自食物本色、背景色和光影层次的配合。保持食物和白色餐具的中性白平衡；红番茄、绿色蔬菜、棕色烤制表面分别准确，不用全图滤镜把它们染成同一种颜色。背景通常选择一主色、一辅助色和必要的中性色，具体多少由该风格决定。

## 4. 每个商品留一份简短设计记录

写入本任务已有 manifest 或其逐图附页，不另建平行项目。下面是字段模板，不是已核实事实；`null` 表示尚未确认。

```yaml
item_id: <本次商品编号>
asset_id: <本次资产编号>
source_role: authoritative-dish | demo-fixture
source_ref: <当前可访问的商品图>
style_ref: <可选审美图；只迁移背景、光线、构图>
quality_reference_ref: <用户认可的质量参考；没有则为 null>
placement: <真实用途>
visible_locks: [<逐项写可见特征；不写猜测>]
source_strengths: [<原图要保留的优点>]
source_issues: [<确实存在的问题>]
change_goal: subtle | strong-brand | style-exploration
approved_changes: [<本次允许改动的内容>]
style_id: F01-F10
selection_reason: <一句可检查的理由>
palette: <品牌色优先；说明每种色用在什么位置>
composition: <主体位置、占比按宽或高明确口径、留白、保留原视角>
render_mode: background-only-composite | reference-edit | concept-generation
requested_ratio: <用户要求>
supported_ratio: null
submitted_ratio: null
actual_pixels: null
expanded_prompt_check: pending | checked | unavailable
visual_check: not-run
retry_limit: <按当轮授权确定；未知时不付费重试>
```

不要在模板里写私人路径、项目 ID、API Key 或默认“积分无限”。输入路径由使用者提供。质量参考只提供审美目标，不能成为另一家店的菜品、Logo 或经营事实。

## 5. 用固定顺序组装，不让扩写改掉硬要求

### 参考图编辑或明确授权的概念图

从 [食品风格模板](food-style-prompts.md) 取公共骨架和一个 F 模块，按顺序填入：

1. 本次用途、商品编号、输出一张独立图片。
2. 实际附件映射：商品图、风格图、品牌资产分别是什么。
3. 从 [六层锁](lock-system.md) 原样插入适用的锁，再附该商品的可见特征。概念图仍保留概念状态，不能升级成真实菜品。
4. 选中的 F 模块、品牌配色、明确的构图与当前商品材质要求。
5. 本次比例和无字要求；价格、Logo、活动说明等走后续确定性图层。

一张图的 Prompt 不能同时要求“主体占满画面”和“上半部全部留白”。占比必须说明按画面宽度还是高度；高杯和横向餐盘分别构图，不把同一个尺度复制给整批。没有数量依据时写“保持来源图可见数量”，已确认两片柠檬时必须写“两片”，不能扩成“一或两片”。

逐商品补充重点：玻璃饮料检查杯口、杯脚、折射、液面、冰和配料；肉类检查生熟颜色、纹理、切面与酱汁；蔬菜检查本色与叶片边缘；甜品检查层次、奶油和巧克力反光。只写图中可见的东西，不为了适配风格增加配料、杯壁水珠、蒸汽或搭配酒瓶。新增效果必须在 Change Set 内，且不暗示不实温度、份量或成分。

### 严格保留原菜品的背景生成

改用风格库里的“背景层骨架”。明确要求画面中没有食物、盘碗或杯子，给原照片预留位置；不要同时粘贴“请展示菜品”的正向指令。依据原图匹配视角与光向，生成后用原图做确定性合成。没有可信抠图或透明玻璃无法干净合成时，保留完整照片卡；不要为了无缝换背景重绘主体。

### 提交前核对

- 将用户简报、组装 Prompt 和实际工具参数并排核对：商品、附件角色、数量、保护区域、比例、风格、张数逐项一致。
- 若执行 Agent 会二次扩写且支持查看最终 Prompt，核对扩写后的文本再提交；已提交才可见时作为事后检查。不能读取就标记 `unavailable`，不能声称已检查内部提示词。
- 比例按当前实际接口能力确认。要求 4:5、实际仅支持 3:4 时，不能静默改写；使用当前接口明确支持的精确尺寸，或在获准后改变画幅/扩展背景。能力不明时保留 `null`，不填猜测。
- 附件名、路径和 `image_1` 等引用标记按本任务的实际上传结果映射。模型专有标记由对应运行适配器处理，不能只写一个不存在的“参考图”。

## 6. 看成图后再扩量

先执行 [视觉验收表](qa-checklist.md) 的食品品牌图检查。用户只要求编写提示词或修改 Skill 时，到此交付模板，不额外调用图片服务。

需要新图且已有费用与素材授权时，先做能代表本批最难问题的一张：透明杯、浅色食物或复杂摆盘。若用户明确要求整批并行，可并行已批准风格的同类商品；尚无样张验证的新风格不因批量请求自动算通过。新增风格或明显不同的材质至少留一张实际样张检查。

验收保留原图、生成图和质量参考，在相同显示尺度下检查约 320px 缩略图及 100% 局部。数字仅是检查尺寸，不是平台规定或审美评分。逐项记录 `pass / revise / not-checked`：

| 检查项 | 通过的证据 | 不通过怎么改 |
| --- | --- | --- |
| 商品身份 | 数量、器皿、配料、颜色、局部纹理与来源一致 | `revise-dish`；回到原图或确定性合成 |
| 食欲与真实感 | 食物清楚、色彩可信；无塑料表面、假高光或损坏玻璃 | `revise-style`；改光线或背景，不能美化成另一道菜 |
| 构图 | 缩略图一眼认出商品；留白、主体尺度和裁切符合用途 | `revise-layout`；重构图，不拉伸食物 |
| 品牌变化 | strong-brand 任务的两项预定变化确实出现，食物不比原图灰暗 | `revise-style`；定向改变背景结构/材质，不仅重复加饱和度 |
| 系列一致 | 同组光线、背景语言、尺度与品牌色能看出同一套设计 | `revise-style`；收敛离群图，保留合格图 |
| 质量参考 | 与用户认可的图比较食物质感、色彩分离和空间层次，写具体差距 | 无参考则标记 `not-checked`，不能声称达到某张未知样张的质量 |
| 文件与参数 | 文件实际存在、可解码；读取真实宽高核对请求比例 | 比例不符为 `revise-layout`，不能用任务文字里的尺寸冒充实测 |

有关键项未查或失败，就不标成品通过。图片通过、用户审美批准、真实门店验证、公开发布是四个独立状态；一个不能代替另一个。自动检查或分数不能证明“比原图更好看”。

重试只改失败项，保留原图与已通过资产；每次记录失败原因和具体修改。按授权的次数/费用上限停止，未授权不继续扣费。重复失败时降级为背景＋照片卡，或说明缺少合适原图，不进行无止境抽卡。

## 7. 给其他人复用时保留什么

- 随 Skill 保留本文件、风格库、输入与锁、QA 和 eval；所有必需引用都用包内相对路径。
- 模板中的配色和示例不是任何门店的既定品牌；运行时按使用者资料填写，不继承原项目的名称、账号、价格、32 张数量或付款授权。
- 原项目图片不因作为审美参考就获得分发权。无参考图片仍能使用文字模板；需要附图时由使用者提供获授权素材，未经许可不把私人图包进公开发行包。
- 模板提高可重复性，不能保证任一模型、任一原图一次达到同样审美。新风格模板默认 `pending-generation`；真实门店状态仍为 `pending-real-store`，用实际样张与验收证据更新。

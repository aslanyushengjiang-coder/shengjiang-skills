# 知识库自检规则

> 每次执行知识库自检前读取。脚本负责发现线索，Agent 负责结合原始文件判断真假。

## 优先级

### P0：立即处理

满足任一条件：

- Agent 启动入口缺失，无法加载核心上下文；
- `AGENT.md / AGENTS.md` 镜像冲突，导致不同 Agent 使用不同规则；
- `INDEX.md` 或入口引用的关键路径失效；
- 同一目录存在多个“最终版 / 最新版”，且没有规则说明当前版本；
- 知识库内出现 `.env`、凭证、Cookie、私钥或密码文件；
- 当前回答可能因此读取错误事实或暴露敏感数据。

### P1：建议处理

- 主要目录没有进入导航；
- `00.收件箱/` 存在长期未处理资料；
- 当前工作文件长期没有更新；
- 根目录散落大量无归属文件；
- 出现依赖目录、缓存、构建产物或嵌套仓库；
- 大量同名文件导致检索时难以区分；
- 日志、纠正记录或巡检记录长期缺失。

### P2：保持现状

- 历史版本已经明确归档；
- 构建产物有清楚用途和保留说明；
- 目录不完全对称，但职责清楚；
- 某些区域暂时没有索引，但不会影响高频任务；
- 为了审计或回溯而有意保留的重复文件。

P2 不是“低优先级问题”，而是明确告诉用户哪些地方不要为了整齐乱动。

## 检查方法

### 入口链路

1. 检查 `AGENT.md`、`AGENTS.md`、`CLAUDE.md` 是否存在。
2. 比较 `AGENT.md / AGENTS.md` 内容是否一致。
3. 读取启动序列，确认被引用文件真实存在。
4. 检查 `CLAUDE.md` 是否导入主入口或包含等价规则。

### 导航与断链

1. 检查 `INDEX.md` 中的 Markdown 链接和明确路径。
2. 检查根级及主要目录 README 的相对链接。
3. 模板占位、命令示例和通配符不是断链，不要误报。
4. 路径失效时先确认是迁移、改名还是历史示例。

### 版本冲突

1. 找出带“最终版、最新版、final、latest”的文件。
2. 同目录出现两个以上时读取局部索引和正文状态说明。
3. 有明确主版本规则时降为 P2；没有时列为 P0 待确认。
4. 不根据修改时间自动宣布最新版，时间只是一条证据。

### 敏感文件

只检查文件名和路径，不读取内容。重点包括：

- `.env`、`.env.*`
- `credentials.json`、`secrets.*`
- `cookies.*`、浏览器配置目录
- 私钥、密码库、聊天数据库

发现后只说明位置和风险，不在报告中输出任何值、URL token 或密钥片段。

### 积压和时效

- 收件箱默认以 30 天作为提醒线，不自动删除。
- 当前工作文件默认以 14 天作为提醒线；用户有其他节奏时按其规则。
- 时效提醒不等于内容失效，仍需结合业务判断。

## 误报处理

遇到以下情况先降级或排除：

- 文档中的示例路径；
- 第三方 Skill 自带的脚手架和测试夹具；
- 明确标记为归档、历史或废弃的目录；
- 嵌套代码项目合法存在的 `.git`、依赖和构建目录；
- 为对照、审计或回滚保留的重复版本。

巡检不是“找茬比赛”。每个问题必须说明：真实路径、证据、可能影响和建议动作。

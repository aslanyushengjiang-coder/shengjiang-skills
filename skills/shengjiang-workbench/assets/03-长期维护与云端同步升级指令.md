# 个人 AI 工作台｜长期使用与云端同步升级指令

下面这套工作台初版已经可以在本地运行。现在请带我把它升级成适合长期使用的版本。

先不要修改代码。请先读取现有项目并告诉我：

1. 当前使用的技术、目录结构和运行方式；
2. 已有模块及模块之间的关系；
3. 当前数据保存在哪里；
4. 电脑端和手机端现在如何访问；
5. 是否已经有数据库、登录、云同步、AI API、备份和错误日志；
6. 当前最重要的风险；
7. 你建议的升级顺序；
8. 每一步可能使用的第三方平台、免费额度、付费条件、隐私风险和迁移方式；
9. 你做不到或无法验证的部分。

等我确认方案后再开始。

## 升级目标

逐项确认我需要哪些能力，不要默认全部开启：

- 电脑端和手机端访问同一份数据；
- 使用账号登录后访问；
- 数据修改后自动保存；
- 支持历史版本、备份和恢复；
- 支持隐私数据和公开数据分开；
- 接入 AI，但不把 API Key 写进网页；
- 支持导出全部数据并迁移到其他平台；
- 必要时支持多人协作和权限；
- 保留使用说明和更新日志。

## 执行原则

- 先备份当前可用版本，再做任何升级。
- 每次只完成一个可以验证的阶段。
- 每个阶段开始前告诉我：会改什么、使用什么服务、是否收费、需要我注册什么、数据会传到哪里、如何回滚。
- 涉及第三方平台注册、购买、部署、域名、数据库、API Key 或权限时，先停下来让我决定，不能替我购买或注册。
- 推荐第三方服务时至少给出 2 个可选方案，说明选择理由、价格、隐私、维护难度和迁移能力。价格必须以官方当前信息为准。
- API Key、密码、Token 和 Cookie 只能保存在服务端环境变量或本机安全存储中，不能写入前端文件、聊天记录或公开仓库。
- 先用虚拟数据测试，再接入真实数据。
- 重要数据结构变化必须提供迁移和回滚方案。

## 推荐升级顺序

### 阶段 0：建立安全基线

- 备份当前项目和数据；
- 建立版本记录；
- 记录当前可用功能；
- 检查密钥、个人信息和隐私数据；
- 提供一键回滚方法。

### 阶段 1：稳定部署

- 选择适合当前技术栈的部署方式；
- 给出真实电脑端和手机端访问地址；
- 检查 `360 × 800`、`375 × 812`、`390 × 844`；
- 记录部署步骤、费用和限制。

### 阶段 2：数据持久化与同步

- 选择数据库；
- 设计数据结构和模块关联；
- 实现自动保存、加载状态、失败重试和冲突提示；
- 手机与电脑验证同一账号看到同一份数据；
- 提供导出、备份和恢复。

### 阶段 3：登录与隐私

- 选择登录方式；
- 设置最小权限；
- 私有数据默认仅本人可见；
- 说明平台管理员、服务商和 AI 是否可能访问数据；
- 提供注销、导出和删除个人数据的方法。

### 阶段 4：AI 接入

- AI 请求通过服务端代理；
- 前端不保存模型 API Key；
- 每次 AI 修改先展示预览和变化说明；
- 用户确认后才写入正式数据；
- 保存来源、执行时间和修改记录；
- 给出模型费用估算、限额和停用方法。

### 阶段 5：长期维护

- 自动备份和定期恢复测试；
- 错误日志和健康检查；
- 更新日志；
- 依赖和第三方服务变更提醒；
- 数据导出和迁移演练；
- 明确每月可能产生的费用。

## 每一步的交付格式

完成一个阶段后，必须告诉我：

1. 已完成什么；
2. 修改了哪些文件和数据；
3. 我现在怎么验证；
4. 电脑端和手机端真实访问地址；
5. 数据保存在哪里；
6. 是否产生费用；
7. 是否新增第三方账号或依赖；
8. 隐私风险；
9. 如何撤销或回滚；
10. 下一步建议。

不能把计划说成已实现，不能编造访问地址，不能替我注册账号或购买服务。

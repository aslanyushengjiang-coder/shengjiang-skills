# 长期升级路径

## 先判断真正需求

| 用户说法 | 可能需要 |
| --- | --- |
| 手机电脑都能看到同一份数据 | 云数据库或同步服务 |
| 只能自己访问 | 登录与访问控制 |
| 团队一起编辑 | 用户体系、权限和冲突处理 |
| 让 AI 分析资料 | 后端代理、模型 API、资料权限 |
| 自动保存和历史版本 | 数据库、版本记录、备份 |
| 公开分享 | 部署平台、域名和公开范围 |

## 方案说明模板

每个候选方案都说明：

1. 能解决什么；
2. 不能解决什么；
3. 数据放在哪里；
4. 是否需要注册第三方；
5. 免费额度和付费触发条件；
6. 维护难度；
7. 如何导出和迁移；
8. 隐私与密钥风险。

## 安全规则

- API Key 只放服务端环境变量或用户本机安全存储；
- 禁止把密钥写入 `app.js`、`config.js` 或公开仓库；
- 第三方价格和额度可能变化，执行前查询官方信息；
- 接入真实数据前先用虚拟样本验证；
- 涉及批量上传或删除时先备份并确认。

## 推荐升级顺序

```text
本地可用
→ 稳定备份
→ 部署访问
→ 登录与数据同步
→ AI 接入
→ 自动化
→ 多人协作
```

不要一开始就堆齐所有能力。

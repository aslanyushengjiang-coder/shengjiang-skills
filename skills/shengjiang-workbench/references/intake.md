# 工作台需求诊断

## 最小访谈

按现有信息跳过已经回答的问题。

1. 这个工作台主要给谁用？他的角色是什么？
2. 最希望它帮你完成的一件事是什么？
3. 你每天或每周反复做哪些工作？
4. 这些工作通常从什么资料开始，最后产出什么？
5. 现在最容易忘记、找不到或重复做的三件事是什么？
6. 主要在电脑、手机还是两者一起使用？
7. 哪些能力首版必须有？哪些可以以后再做？
8. 是否涉及隐私、客户资料、账号或 API Key？

## 访谈收束

将答案整理为：

```markdown
用户角色：
核心目标：
高频工作：
输入：
处理动作：
输出：
主要痛点：
首版必需：
二期可选：
明确不要：
设备：
数据敏感性：
```

无法确认的内容写“待确认”，不要替用户编造。

## 模块判断

只在同时满足以下条件时建议独立模块：

- 用户会反复进入；
- 有明确输入和输出；
- 与其他模块的职责能区分；
- 首版存在真实使用场景。

只展示信息、没有真实动作的内容优先放到首页卡片，不要单独建模块。

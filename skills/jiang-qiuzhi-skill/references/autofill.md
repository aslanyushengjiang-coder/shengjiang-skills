# 自动网申：受监督的逐岗代填，不是自动最终投递

## 前置授权

确认这批岗位清单、官方/经官网确认的ATS链接、可代填资料、每岗简历版本，以及“上传会把简历提供给该站点”。
这是对明确批次的代填授权，不是任意网站、任意方向或后台运行的空白授权。
先用 `jobctl resume register` 注册已核对文件；填表前校验manifest中的SHA256与实际文件一致。

## 逐岗流程

打开新标签页 → 读取可见字段和页面 → 建立字段映射 → 按已确认值填入 → 每页回读 →
上传对应文件并核对显示的文件名 → 检查错误和必填项 → 保存草稿（若站点支持） → 停在最终提交前。
单独记每个岗位，不共享错方向简历。不关闭用户原有标签页。
“下一步”或保存草稿也可能向站点传输数据；在已有明确代填授权范围内执行，遇效果不明按钮先停。
本包没有默认通用选择器，不盲点、不用脚本猜按钮、不伪称有适配全部ATS的自动化。

可代填：已确认姓名、联络方式、教育经历、项目/实习、技能、到岗日期；只上传已确认版本。
薪资、地点/出差/加班偏好、推荐人、主观开放题：先确认，不用猜测的答案提高完成率。
登录、密码、验证码、身份证/金融账号、健康和背景信息、背景调查同意、法律声明、真实性承诺、签名：交给用户。
最终提交始终由用户本人检查并完成；不规避验证码、人脸、登录墙和站点限制。

## 结果与断点

每岗写入 `form-results.json`：岗位ID、URL、resume_id、sha256、填写字段名、
文件名回读、blocked_fields、当前URL、last_safe_step、draft状态、requires_user_action。
不把明文电话/邮箱、密码、Cookie放入运行日志。截图尽量遮蔽个人资料。
状态使用draft_filled / ready_for_review；遇阻塞停当前站，不重复失败循环。
可继续其他已获授权且无需新确认的岗位，但不得承诺无人值守跨站填完。

用户完成提交后，只有观察到成功回执或用户明确报告才写submitted；保存草稿/点击下一页都不是提交成功。
本站未实际测试就标“待站点实测”。只能输出字段表时标“未执行网页代填”。

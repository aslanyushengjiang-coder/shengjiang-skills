# 全量秋招表导入与初筛

## 先检查，再全量处理

支持CSV、TSV、XLSX。旧版XLS、加密工作簿、图片表格不能直接读；请宿主使用已获授权的转换能力，
无法转换就明确停止，不把只读到一页当作处理全表。读取公式缓存，不运行任何公式或宏。
本包XLSX读取器不会计算公式，不读取浮动文本框，也不能恢复损坏的源文件。

先观察所有sheet的表头；默认在每张表前30个非空行寻找公司+岗位表头。
常见别名可自动识别；复杂列名通过 `--mapping <列映射.json>` 指定“源列名→标准字段”。
含多个同名表头、单元格超链接、合并表头和没有缓存的公式要看import-report，不能忽略警告。
每行保留源文件、sheet和行号、原字段。未识别sheet不会算成成功导入，报告列出原因。

```text
python <SKILL_DIR>/scripts/jobctl.py --data-dir <DATA_DIR> jobs import --file <秋招表.xlsx>
python <SKILL_DIR>/scripts/jobctl.py --data-dir <DATA_DIR> jobs screen --as-of <用户所在时区的YYYY-MM-DD> --out <WORKSPACE>/筛选结果
```

## 初筛顺序

全量统计 → 精确规则去重 → 届别/类型/明确城市硬限制/截止日期等字段检查 → 方向关键词初筛 → 分桶。
未知不是不符合，也不是默认通过。缺JD或完整资格条件时只交付初筛结果，不称“全量精读完毕”。
脚本分为“优先核实”“待补信息”“不匹配或过期”“已投递”，每行带理由。
不根据推断的人口属性或缺失信息淘汰；学历专业等未被脚本覆盖的硬要求仍必须逐JD人工/Agent精读。
脚本关键词命中数只用于列表排序，不是岗位匹配分。

按候选方向、先确认的偏好、可行性、真实截止日期排序；截止不详的不能凭空编出日期。
优先核实清单回到官网再检查，才给出“建议投/暂缓/资格待确认”。允许用户调整筛选规则后重跑全量。

## 必须交付

1. `import-report.json`：扫描行数、导入有效行、唯一岗位、新增/更新/重复数、跳过与异常详情。
2. `all-screened.csv/json`：每一条唯一岗位及其桶、命中词和原因。
3. 各桶CSV、`screen-report.json`：可核对的统计。保留最初原表不覆盖。
4. 完整JD精读清单与尚未核实数；别将程序完成初筛说成官网全部核实。

5000行回归测试使用临时生成的虚构数据。它证明的是本地处理逻辑，不证明已经附赠真实5000条岗位。

## 多用途工作簿

文件同时包含“岗位总表”和“投递进度”等表时，先确认导入工作表范围，不能把进度表作为新岗位导入。

```bash
python scripts/jobctl.py --data-dir "/独立求职工作区/data" jobs import --file "/工作区/求职工作簿.xlsx" --sheets "岗位总表"
```

`--sheets` 后可给多个完整工作表名；名称不存在会报错，不会悄悄改用别的表。
不提供该选项时读取所有可识别岗位工作表，并在报告中列出跳过项。
工作簿模板与数据库之间没有自动双向同步；由用户授权 AI 导出、整理或人工维护。

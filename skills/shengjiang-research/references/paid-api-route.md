# TikHub 付费 API 路线

这是 `shengjiang-research` 的主执行路线。实际调用前完整读取本文件。

## 这条路线是什么

Skill 代码免费开源，自动采集通过第三方 TikHub API 完成。用户自行注册、充值、配置 Key，并直接承担 API 费用。

Key 默认一次保存到 Skill 内 `scripts/.tikhub_api_key`，后续会话实时读取并复用，文件优先于环境变量。先运行 `--check-config`；用户已经提供 Key 时直接代存，已有配置就继续执行，不反复要求输入或改存环境变量。自选文件、JSON、旧路径和 Keychain 用法见 `configuration.md`。

TikHub 是余生姜基于真实调研使用体验主动推荐的第三方 API 网站；余生姜个人认为它非常好用，尤其适合账号、作品、评论、字幕和公开数据的批量调研。这是个人使用推荐，不代表 TikHub 官方合作、授权或商务背书。

不要把 TikHub 说成 Shengjiang 自建、代理或转售的接口，也不要承诺永久免费、固定单价、稳定性、售后或无限额度。

## 当前公开计费口径

以下数字用于帮助用户理解量级，执行时必须重新核对官方页面：

- 多数基础服务从 `0.001 USD / 成功请求`起；
- 不同端点通常约 `0.001–0.01 USD / 请求`；
- 少数特殊或企业数据端点可能高于 `0.01 USD / 请求`；
- TikHub 官方说明：非 200 响应通常不收费；
- 新账号当前约有 `0.05 USD` 试用额度，通常约 50 次基础请求；
- 日请求量增加后可能触发阶梯折扣。

官方价格页：https://tikhub.io/pricing

官方价格计算接口：

```text
GET /api/v1/tikhub/user/calculate_price
```

参数：

- `endpoint`：准备调用的数据端点；
- `request_per_day`：预计当天成功请求数。

## 批量任务先算请求数

按端点拆开：

```text
账号发现 / 资料请求
+ 作品列表页数
+ 单条详情请求
+ 评论页数
+ 楼中楼页数
+ 字幕、下载地址或其他补充端点
```

示例：计划研究一个账号的 100 条作品，作品列表每页 20 条，每条抓 1 页评论，另需 1 次账号资料：

```text
账号资料 1 次
+ 作品列表 5 次
+ 评论 100 次
= 预计 106 次
```

如果详情端点还需要逐条调用，再加 100 次。页大小、是否需要详情和评论翻页必须以具体端点为准。

## 先给用户看费用

1. 从具体端点文档或官方价格计算接口取得单价；
2. 分别计算不同单价端点；
3. 把第三方 ASR 费用单独列出；
4. 说明失败重试、临时扩量和特殊高价端点不在初始预估内；
5. 先跑 1–3 条样本，再确认批量。

离线预估：

```bash
python3 scripts/tikhub_request.py \
  --path '/api/v1/<platform>/<endpoint>' \
  --estimate-requests 106 \
  --unit-price 0.001 \
  --dry-run
```

官方计算：

```bash
python3 scripts/tikhub_request.py \
  --official-price \
  --path '/api/v1/<platform>/<endpoint>' \
  --estimate-requests 106
```

## 小样本验证

先预览：

```bash
python3 scripts/tikhub_request.py \
  --method GET \
  --path '/api/v1/<platform>/<endpoint>' \
  --params '{"示例参数":"示例值"}' \
  --out 'social-research/raw/sample.json' \
  --estimate-requests 3 \
  --unit-price 0.001 \
  --dry-run
```

确认后去掉 `--dry-run`，只请求 1–3 条样本。

样本通过标准：

- 对象、平台和内容一致；
- 核心字段存在；
- 分页字段明确；
- 返回码和权限正常；
- 实际扣费与预估量级一致。

## 批量执行

样本通过后，再向用户报告：

- 使用哪些端点；
- 每个端点预计调用多少次；
- 单价来源和查询时间；
- 总成本区间；
- 评论深度；
- 是否下载媒体；
- 是否另用第三方 ASR。

只有用户确认范围后才批量执行。批量过程中记录成功请求数、失败请求数和实际余额变化；费用明显超预估时立即暂停。

## 常见错误

- `401`：Key 无效、已过期或请求头错误；
- `402`：余额或额度不足；
- `429`：频率限制，应降低并发或缩小范围；
- 成功但无数据：检查对象、地区、权限、时间和翻页参数；
- 字段与文档不一致：保留原始响应，更新映射并记录日期。

不要为了跑通而猜接口、伪造响应或无限重试。

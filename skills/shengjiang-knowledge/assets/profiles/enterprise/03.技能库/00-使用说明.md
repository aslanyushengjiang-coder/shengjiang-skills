# 技能库：任务怎样执行，做到什么程度算完成

管理团队可重复使用的工作方法、检查表、模板与工具调用方式。先读本说明与本库 `_资料索引.md`，按具体任务选择流程。普通 SOP 可以直接使用；可安装 AI Skill 只是一种执行形式。

## 建议子库

下表提供方法分类，按机构业务和真实资料启用。已有成熟目录不改名；有资料或明确执行需求再创建子目录。行业常识可形成待验证建议，不能写成该团队已经采用的制度。

| 建议子库 | 放什么 | 完成时看什么 |
| --- | --- | --- |
| 01.调研研发与采购 | 用户/市场调研、资源考察与比选、产品研发、课程研发、供应商评估、采购确认 | 需求和资源有来源，产品限制与成本有依据；采购确认有真实凭据 |
| 02.内容获客与渠道 | 定位与选题、活动宣传、公众号/海报/视频制作、社群运营、渠道推介与合作流程 | 内容对应有效产品，素材可用，尺寸文字等检查合格，发布状态有实际证据 |
| 03.咨询销售与报价 | 需求访谈、咨询接待、方案设计、定制报价、利润核算、投标应答、合同与成交交接 | 需求覆盖、报价条件和计算正确，内部成本与对外报价分开，承诺有依据 |
| 04.排期计调与行前准备 | 开团条件、订房订车订餐、名单确认、人员排班、分组分房分餐分车、物料采购与行前通知 | 总量核对、资源确认、时间衔接、特殊需求和未解决冲突清楚 |
| 05.现场执行与安全应急 | 签到、带队、交接、现场活动、设施检查、天气调整、应急响应及事件上报 | 按本机构适用的预案、资质与责任分工执行；实到与执行记录可追溯，缺少安全条件时停止依赖环节并交负责人处理 |
| 06.教学带队与学习评价 | 通用教学组织、分龄引导、导师带教、观察记录、学习评价、研学手册制作方法 | 适龄与教学目标清楚，具体表现有观察证据，不虚构孩子的成长结论 |
| 07.售后复盘与客户运营 | 返图、个人反馈、回访、投诉处理、退款办理、结营总结、经营复盘、会员与转介绍运营 | 服务承诺有处理结果，统计有原始依据，改进建议与已验证方法分开 |
| 08.岗位协作与工具使用 | 岗位职责、交接、培训、审批规则、合同/财务操作、知识库维护、软件与 AI Skill 使用说明 | 负责人和交接产物明确；工具可访问、执行有权限、失败后可继续；凭据不写入知识库 |

## 每个流程的执行约定

按需要补齐下面的信息，可以在已有文档中增加章节，无需强制拆成多张卡片：

| 要素 | 要说明什么 |
| --- | --- |
| 触发与范围 | 用户说什么或出现什么情况时使用；适合哪些机构角色与业务 |
| 输入与事实来源 | 需要哪个客户、产品、团期、资源、名单及采用版本；缺哪些信息不能继续 |
| 权限与负责人 | 谁执行、谁核验；哪些动作已授权，哪些涉及外发、支付或负责人批准 |
| 步骤与工具 | 按真实操作顺序执行；工具入口、依赖条件和不可用时的处理方式 |
| 输出与保存位置 | 交付什么、写回哪个产品/客户/团期，草稿和采用状态如何标记 |
| 验收 | 可检查的条件，如金额、人数、日期、素材授权、承诺与实际结果 |
| 异常与继续 | 失败停在哪一步、已完成什么、还缺什么；保留可继续记录，避免重复发送或重复付款 |
| 反馈与维护 | 流程负责人、适用日期、验证依据；何时需要更新方法 |

这些字段是工作约定，不能把编写约定本身当成脚本或自动化已经实现。只有已安装并能找到的工具才登记为可调用。

## 模板、事实与实际记录

空白报价模板、通用教案设计方法、分车规则、海报设计规范留技能库；某产品的具体报价规则、教案和海报留产品库；某客户的报价与服务记录留客户库。流程执行时引用真实数据，不能把示例金额、示例客户、历史日期带进成品。

生成的结果回到业务对象，不保存到 Skill 安装目录。已有技能清单可登记名称、任务、安装位置、状态和验证日期；安装成功、调用成功、业务结果通过分别记录。

## 验证与改进

每个关键流程至少使用一条真实、获授权的业务任务验证：输入可回读，输出可检查，异常有记录。仅文档走查标为“规则已检查”，仅测试数据运行标为“测试通过”；两者均不能标成团队实际采用。

任务失败时先记录在实际业务档案；同类问题重复且原因明确，再更新本流程并保留依据。全局协作纠正才写 system，产品价格回产品原文，客户状态回客户记录，避免所有反馈都堆进系统规则。

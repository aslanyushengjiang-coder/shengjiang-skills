# 自媒体工作台模式

## 目标

把零散的对标链接、逐字稿、评论、灵感、文稿和发布数据接成一条可追溯的内容生产链：

```text
账号定位
  → 对标调研 / 用户洞察 / 素材
  → 选题池
  → 草稿
  → 审核
  → 定稿
  → 待发布
  → 已发布与复盘
```

每条内容都要能回答四个问题：来源是什么、现在到哪一步、最终发在哪里、数据表现怎样。

## 初始化

先预览：

```bash
python3 scripts/init_knowledge_base.py \
  --root "<绝对路径>" \
  --name "<知识库名称>" \
  --profile creator
```

用户确认后再加 `--apply`。脚本只创建缺失文件，不覆盖已有文件。

已有知识库不要为了套模板重建。先把现有目录映射到下表，给出路径级预览，再补缺失入口或局部索引。

## 目录职责

| 路径 | 放什么 | 必须保留 |
| --- | --- | --- |
| `01.资料库/01.账号定位/` | 身份、目标人群、内容承诺、平台和表达边界 | 用户明确说过的定位；未知项标待确认 |
| `01.资料库/02.对标调研/` | 对标账号、作品原文、逐字稿和拆解 | 平台、作者、原链接、发布日期、抓取日期、原始路径 |
| `01.资料库/03.用户洞察/` | 评论、提问、访谈和真实反馈 | 原话、来源、日期；AI 归纳与原话分开 |
| `01.资料库/04.素材库/` | 可复用案例、数据、图片、视频、音频和引用 | 来源、版权或使用边界、原始路径 |
| `02.输出区/01.选题池/` | 候选选题和选题证据 | 对标或用户问题的来源，不凭空造选题依据 |
| `02.输出区/02.草稿/` | 正在写的初稿 | 一条内容只保留一个当前工作副本 |
| `02.输出区/03.审核/` | 待事实、口条、平台和合规审核的稿件 | 审核问题与版本记录 |
| `02.输出区/04.定稿/` | 已确认可拍或可发布的唯一当前版本 | 定稿日期和确认人 |
| `02.输出区/05.待发布/` | 成品、封面、标题、简介、标签和排期 | 目标平台和计划发布时间 |
| `02.输出区/06.已发布与复盘/` | 发布链接、真实数据和复盘结论 | 平台、发布时间、标题、链接、数据采集时间 |

大文件不必复制进多处。保留一个原件，在内容卡或索引里写绝对路径或稳定相对路径。

## 资料接入

1. 先用 `scan_materials.py` 建只读清单。
2. 按来源读取代表内容，不根据文件名猜正文。
3. 对标原文与 AI 拆解分开保存；用户评论原话与 AI 洞察分开保存。
4. 生成接入预览，明确每批资料进入哪个目录、更新哪个索引、原件是否保留。
5. 用户确认后写入并更新局部索引；只有新增高频入口时才改根 `INDEX.md`。

常见路由：

| 输入 | 建议归属 |
| --- | --- |
| 对标账号主页或作品链接 | `01.资料库/02.对标调研/` |
| 视频字幕、逐字稿、文章原文 | 跟随对应对标或素材条目，保留原链接 |
| 评论区、私信提问、访谈原话 | `01.资料库/03.用户洞察/` |
| 一闪而过且未验证的灵感 | `00.收件箱/` |
| 有证据、准备评估的选题 | `02.输出区/01.选题池/` |
| 图片、视频、音频和数据案例 | `01.资料库/04.素材库/` |

## 内容状态流转

- 默认顺序：选题池 → 草稿 → 审核 → 定稿 → 待发布 → 已发布与复盘。
- 状态变化时移动当前工作文件或更新唯一内容卡，不复制出“最终版2”“最终版真的最终”。
- 用户没有确认定稿、发布或排期时，Agent 只提案，不替用户拍板。
- 发布后记录真实链接和数据。点赞、评论、收藏、转发、播放、涨粉等字段按平台实际可得项填写；没有就留空，不能估算。
- 复盘结论必须区分事实数据、用户判断和 Agent 推测。

## 健康检查增量项

除通用巡检外，额外检查：

1. 对标和选题是否缺真实来源；
2. 同一内容是否散落多个“最终版”；
3. 定稿、待发布和已发布状态是否互相冲突；
4. 发布条目是否缺平台、链接或数据采集时间；
5. 原始素材是否出现重复副本或悬空路径；
6. 收件箱、草稿和待发布是否长期积压。

这些规则需要业务判断，脚本输出只作线索。修复前仍要给出路径和证据，并让用户确认。

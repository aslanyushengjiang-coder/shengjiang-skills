# 资料接入与结构化规则

> 用户给出文件、文件夹、录音、网页、PDF、表格或旧知识库，希望“整理进系统”“让 AI 以后能找到”时读取。

## 核心原则

不要先按主题硬塞文件。先判断五件事：

1. **来源**：外部资料、用户本人、客户现场、团队流程还是项目过程？
2. **所有权**：这是外部观点、用户明确判断，还是已验证的业务事实？
3. **下一步用途**：保存、研究、输出、项目执行、复盘还是固化为规则？
4. **事实层级**：原始文件、结构化摘要、导航索引、业务成品还是程序规则？
5. **时效与版本**：是否有日期、当前状态和有效版本依据？

外部知识可以被使用，但未经用户判断或业务验证，不能写成“用户的观点”。

## 标准接入流程

### 1. 建清单

先运行只读扫描：

```bash
python3 scripts/scan_materials.py --source "<资料路径>" --format markdown
```

脚本只登记路径、类型、大小和敏感文件风险，不读取正文，也不复制或移动文件。

### 2. 分批读取

- 先读目录说明、索引、文件名和少量代表文件。
- PDF、Word、Excel、图片、音视频使用当前 Agent 已有的对应读取或转写能力。
- 大批量资料按领域、来源或日期分批，不一次把全部正文塞进上下文。
- `.env`、Cookie、密钥、密码库和聊天数据库只登记风险，禁止读取内容。
- 无法读取的格式标记“待转换”，不要根据文件名编造摘要。

### 3. 给每批资料生成接入卡

使用以下结构：

```markdown
# 资料接入卡

- 来源：
- 原始路径 / 链接：
- 资料时间：
- 作者 / 所有者：
- 内容类型：
- 当前状态：原始资料 / 已提炼 / 待确认 / 已归档

## 核心内容

## 可确认事实

## 外部观点或待验证判断

## 与现有知识库的关系

## 建议归属与下一步用途

## 版本、敏感信息与缺口
```

### 4. 决定落位

| 内容性质 | 默认落位 | 说明 |
| --- | --- | --- |
| 暂时无法判断 | `00.收件箱/` | 只短期停留，进入后续处理队列 |
| 可长期复用的原始资料、案例、参考 | `01.资料库/` | 保留来源、日期和原始路径 |
| 用户自己的长期判断、经历和原则 | `system/USER.md`、`system/PROCEDURES.md` 或专门的自我区 | 必须有用户表达或业务验证依据 |
| 正在制作或已经完成的成果 | `02.输出区/` | 与原始输入分开 |
| 一次真实项目的输入、决策、交付和复盘 | `03.项目档案/` | 保留过程证据和状态 |
| 反复出现的执行流程 | `skills/` 或 `system/PROCEDURES.md` | 先证明会重复且可验收 |
| 纠正和失败经验 | `system/MEMORY_LOG.md` | 重复后再提议升级固定规则 |

原件只保留一个事实源。其他位置放链接、接入卡、摘要或业务产物，不复制多份全文。

### 5. 先预览再写入

```markdown
准备接入：

| 原始资料 | 建议归属 | 新建 / 更新内容 | 原件处理 | 依据 |
| --- | --- | --- | --- | --- |

仍待确认：
- 哪些观点代表用户本人？
- 哪个版本当前有效？
- 哪些资料只保留引用，不复制原件？
```

用户确认后才创建目录、复制原件、写接入卡或更新索引。完成后更新：

- `01.资料库/_资料索引.md`；
- 对应区域 README / 局部索引；
- 根 `INDEX.md`（仅新增高频入口时）；
- `system/log.md`。

## 结构化不等于改写原文

- 原始资料保持可追溯，不用摘要覆盖原文。
- 摘要必须区分“原文事实”“作者观点”“Agent 提炼”“用户判断”。
- 引用数据保留来源和日期。
- 证据不足时写“待验证”，不要补齐看似完整的结论。
